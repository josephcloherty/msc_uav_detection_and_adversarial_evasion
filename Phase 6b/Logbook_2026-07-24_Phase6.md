# Friday 24 July 2026 – Phase 6 classifier scripts and dataset sizing

**Logbook**

- Five classifier families were implemented as paired MATLAB training and test scripts built on the Statistics and Machine Learning Toolbox functions behind Classification Learner: k-nearest neighbours (`fitcknn`), random forest (`fitcensemble`, bagged trees), decision tree (`fitctree`), logistic regression (`fitclinear`) and discriminant analysis (`fitcdiscr`). A shared `prepare_data.m` fixes the operator-observable feature set and produces one seeded, stratified train and test split reused by every model. All eleven files were placed in the Phase 6 folder.
- Each test script reports accuracy, precision, recall, false positive rate and AUC-ROC with the aerial class treated as positive, keeping the false positive rate the emphasised metric at network scale.
- The Phase 5 batch structure was reviewed to size the dataset. Each run is a 60 s simulation of one scenario at a fixed seed, with five gNBs, eight terrestrial UEs and, on average, about two to three aerial UEs; the three scenarios UMa, RMa and UMi are cycled one per run. Ten-second windows at a one-second stride give roughly fifty windows per UE, so a single run yields on the order of five hundred labelled rows.
- Robustness was sized in independent seeds per scenario rather than in rows, because the one-second-stride windows overlap almost entirely and the aerial UEs, at about two to three per run, are the limiting independent unit. The row count therefore overstates the information available, especially for the aerial class.
- A target of about twenty seeds per scenario, that is sixty 60 s runs in total, was set. This yields roughly fifty aerial and one hundred and sixty terrestrial UE trajectories per scenario and around thirty thousand rows, which supports stable per-scenario AUC and a pooled cross-scenario model. About thirty runs were identified as the minimum viable cross-scenario set and about ninety as the point of diminishing returns.
- At the manifest cost of roughly thirteen hours per average run on six workers, sixty runs is about five to seven days of continuous compute, so `phase5_DryRun` should be run on the chosen seed range before committing. Evaluation must use a seed-grouped split; `prepare_data.m` is to be revised to split on the scenario and seed identifiers rather than at random once the dataset exists.

**Deliverables:** D6.1 in progress. Eleven MATLAB scripts were placed in the Phase 6 folder, and a target of sixty 60 s runs, twenty per scenario, was recorded for dataset generation pending a `phase5_DryRun` wall-time projection.
