# Monday 10 August 2026 – Phase 6 restructured for cross-validated selection, per-UE decision and pipeline freezing

**Logbook**

- The Phase 6 deliverable list was revised and the folder rewritten against it. The substantive change is that seeds one to forty-five are now a single development set with no internal hold-out, so grouped cross-validation over those runs becomes the primary evidence rather than an optional companion to a train and test split, and every hold-out run is reserved for Phase 7. The previous structure, which trained on seeds one to forty-four and tested on seed forty-five, was evaluating on what the revised plan treats as development data, and its five test scripts were therefore reporting a quantity the new specification does not ask for. Eleven scripts now stand in the Phase 6 root; `train/`, `test/`, `train_all.m`, `test_all.m` and `phase6_AerialCull.m` were moved to `retired/` along with the result CSVs they produced.
- `prepare_data.m` was rewritten around a declared development range. Seeds are read from the filenames and any run outside the range is refused loading rather than merely excluded downstream, so no Phase 6 script can reach hold-out data even by accident; seed forty-six, the only such run currently on disk, is reported as not loaded. The feature switchboard, the operator-observability guard and the single-feature separability tripwire were carried over unchanged. Two columns previously discarded as bookkeeping, the UE identifier and the window start time, are now retained as side variables, because ordering a UE's windows in time is what the persistence rule and the latency curve are built on and neither could be computed without them. The predictors are handed on as a numeric matrix rather than a table, since every downstream operation on them is a matrix operation.
- The five model definitions were consolidated into a single registry, `phase6_models.m`, which returns for each family its name, a filename-safe key, whether it requires standardised input, a fitting handle and a scoring handle. The previous layout defined each model twice, once in `train/train_*.m` and again in `run_cv.m`, which meant a hyperparameter changed in one place and not the other would have produced cross-validation evidence that did not describe the model eventually frozen. The registry is now the only definition and the freezing script asserts that it still matches the families the cross-validation used.
- The scoring handles were made to return a posterior on a common zero-to-one scale for all five families rather than each family's native score. This is not cosmetic: the per-UE rule averages scores across a UE's windows, and averaging the raw margin of a linear model is not the same operation as averaging a probability. `fitclinear` returns the linear predictor, so the logistic link is now applied to recover the probability exactly, which leaves the ROC unchanged, being monotone, but makes the mean posterior rule meaningful for that family.
- Shared metric and decision-rule helpers were collected in `phase6_util.m` and exported as function handles, so that the ROC construction, the partial AUC, the threshold rule and the per-UE collapse have exactly one definition each. A metric computed two slightly different ways in two scripts is the most likely inconsistency to survive review. The reporting helpers were placed there too rather than as local functions in the stage scripts, so that every stage remains a plain script and its behaviour does not depend on how local functions resolve when the script is called from within the master function.
- `run_cv.m` was rewritten for D6.2. Whole runs are assigned to folds, so no seed contributes rows to both the training and the validation side of any fold, and within each scenario the runs are ordered by aerial prevalence and dealt out serpentine, which balances scenario mix and class prevalence together without any randomness, so the same runs land in the same fold on every execution. Stratifying on prevalence proved necessary rather than decorative: the number of aerial UEs per run ranges from one to six, and ignoring it would have left the folds materially unequal in positive rate.
- Reporting was extended to the partial AUC below a five per cent false alarm rate, normalised by the width of that range so that it reads as the mean recall available there and sits on the same scale as the full AUC. The full AUC integrates over false alarm rates no operator would ever run at, and two models with the same full AUC can differ sharply in the only region that matters at network scale. Every metric is now reported with its dispersion across folds, which is a statement about run-to-run variation rather than about sampling error within a fold, and the per-fold detail is written out alongside the summary.
- The full out-of-fold score vector is retained to `prepared_data/oof_scores.mat`. Every one of D6.3 to D6.6 reads from it rather than refitting, which is what keeps the decision rule, the thresholds, the latency curve and the importance ranking all describing the same set of predictions.
- `per_ue_rule.m` was written for D6.3. The mean posterior over a UE's windows is compared against M-of-N persistence, with the persistence rule expressed as a continuous score so that it has an ROC and the two can be compared on the same footing rather than at one arbitrary operating point. The M-of-N score is defined as the maximum, over every block of N consecutive windows, of the M-th largest score in that block; thresholding that quantity at t is exactly the statement that M of N consecutive windows exceeded t, so the persistence rule and a continuous score are the same object. That identity was checked exhaustively for six parameter pairs against every distinct threshold in a fifty-window sequence.
- Rule parameters are selected on the development folds alone. For each fold the per-UE threshold is derived on the other four and applied to the held-out one, so no parameter is chosen using the UEs it is then scored on, and where no persistence rule beats the mean posterior the mean is kept, on the grounds that it has no fitted parameters to defend. Twenty-six candidate rules are evaluated per family and the full candidate table is written out, not only the winner.
- `thresholds.m` was written for D6.4. Operating points are derived from the pooled out-of-fold scores at a nominal one per cent false positive rate as primary and five per cent as a sensitivity point, separately at window level and at per-UE level, since flagging one per cent of windows is not the same as flagging one per cent of subscribers and the latter is the rate an operator would be held to. The achieved rate is recorded beside the nominal one in every row, together with the false positive count and the size of the negative population.
- That last provision turned out to be necessary rather than pedantic. With roughly three hundred and sixty terrestrial UEs in the development set, the per-UE false alarm rate can only move in steps of one UE, so a nominal one per cent target admits three false alarms and lands at an achieved rate of 0.833 per cent. Quoting the nominal figure alone in Chapter 4 would misrepresent the result, and `prepare_data.m` now prints the granularity at load time so the constraint is visible before any threshold is quoted.
- `latency_curve.m` was written for D6.5. Recall at a fixed false alarm rate is plotted against the number of windows observed, taking windows in time order from the start of each UE's trajectory, with the threshold re-derived at every observation length. Re-derivation is the point of the deliverable and is easy to omit: a per-UE score built from three windows has a different distribution from one built from thirty, so carrying a single threshold across the curve would report a false alarm rate that drifts with observation length. The population is fixed to UEs with at least thirty windows, so the curve reflects observation time rather than a changing mix of UEs.
- `feature_importance.m` was written for D6.6 and reports four views of the same question: out-of-bag permutation importance, single-tree split importance, standardised logistic coefficients and single-feature AUC, each measured fold by fold on the same folds as D6.2 so that the dispersion is a statement about the stability of the ranking. The four are combined by averaging ranks rather than values, because they sit on incomparable scales and averaging the raw numbers would let whichever has the widest range decide the ordering on its own. Literature expectations and the manipulability judgement are read from an editable CSV, generated as a template on first run, with the feature blocks and manipulability defaults pre-filled and the expectation and source columns left for completion; attributing a claim to Rydén et al. or to the AT&T and Verizon patents is a reading of those sources and not something a script should assert on their behalf.
- `freeze_models.m` was written for D6.7. All five families are refitted on the full forty-five development runs and frozen, each with its own imputation medians, scaling constants, decision rule and both thresholds, together with the feature list, the switchboard that produced it, the MATLAB version and the freeze date. The primary classifier is selected on held-out per-UE recall at the one per cent operating point, with the partial AUC below five per cent breaking ties, and the criterion is recorded in the manifest so the choice can be audited rather than taken on trust. All five are frozen rather than the primary alone, both because the exit criterion asks for five pipelines and because a secondary family is worth having if the primary behaves unexpectedly on hold-out data.
- `score_pipeline.m` was written as the sole entry point for applying a frozen pipeline, returning a window score, a per-UE score and a decision at each frozen threshold. Nothing in it is fitted; every constant is read from the frozen file, and it is intended that Phase 7 calls this and refits no part of the pipeline, since an imputation median or a threshold recomputed on hold-out data would leak as surely as training on it would. A master script, `run_phase6.m`, runs the seven stages in order and reproduces every figure from raw CSVs.
- The non-model logic was mirrored in Python and run against the real feature CSVs as a check on the arithmetic and the data plumbing ahead of the MATLAB execution. The development set was confirmed as 23,950 rows from forty-five runs, four hundred and seventy-nine UEs of which one hundred and nineteen are aerial. The fold assignment produced nine runs per fold, three per scenario, with no run or seed spanning a boundary and a residual prevalence spread of 5.5 percentage points after stratification. The partial AUC agreed with direct integration of the ROC to within three parts in a trillion, the threshold rule never exceeded its nominal rate and was confirmed to be the best threshold satisfying it, and the M-of-N identity held in every case tested.
- The same mirror, using a scikit-learn bagged forest in place of the MATLAB models, gives an indicative window-level AUC of about 0.978 with a normalised partial AUC below five per cent false alarm rate of about 0.758, and at per-UE level puts the mean posterior at about 0.891 recall against 0.756 to 0.782 for the persistence rules. These figures are indicative only and are to be replaced wholesale by the MATLAB output; they are recorded because if MATLAB reproduces the ordering then D6.3 will select the mean posterior for most or all families, which is a defensible outcome precisely because that rule has no parameters that were fitted.
- Two items remain outstanding before the phase can be closed. The literature and source columns of the manipulability table are unfilled, and the whole pipeline is yet to be executed in MATLAB, so no result in this entry should be quoted in the chapter.

**Deliverables:** D6.1 reissued against the revised specification. Eleven MATLAB scripts in the Phase 6 root, comprising a shared helper file, a five-family model registry, six stage scripts covering D6.2 to D6.7, a scoring entry point and a master script; the superseded train and test scripts are retired. D6.2 to D6.7 pending the MATLAB execution of `run_phase6.m`, and D6.6 additionally pending the literature expectation and source columns.

## Later the same day – first execution through D6.3, and four defects it exposed

**Logbook**

- The pipeline was executed in MATLAB as far as D6.3. The development set was confirmed as 23,950 rows from forty-five runs, four hundred and seventy-nine UEs of which one hundred and nineteen are aerial, at 24.8 per cent of both rows and UEs; these figures reproduce the Python mirror exactly, which confirms that the loader, the seed filter and the row ordering behave as intended. Eight columns were dropped before the switchboard, five as all-NaN, being the subband CQI spread and the four timing advance columns, and three as constant, being the three retransmission rates, leaving sixty-two predictors of which thirteen are switched on.
- The leakage tripwire stayed silent. The strongest single predictor is the mean neighbour-cell SINR at a single-feature AUC of 0.878, followed by the mean count of neighbours above threshold at 0.843, which is the expected profile with the traffic block switched off and is comfortably clear of the 0.99 warning level. Nothing in the current feature set separates the classes on its own.
- The folds came out as designed: nine runs each, exactly three per scenario, with aerial prevalence running from 21.7 to 27.3 per cent, and no run or seed spanning a boundary. The residual prevalence spread of 5.6 percentage points is the cost of grouping at run level when the number of aerial UEs per run varies between one and six. Worth noting for the write-up is that UMi supplies fifty-one of the one hundred and nineteen aerial UEs from a third of the runs, so the aerial class is not evenly distributed across scenarios even though the runs are.
- D6.2 puts the random forest ahead of the other four families on every measure: AUC 0.981 with a standard deviation across folds of 0.005, normalised partial AUC below five per cent false alarm rate of 0.787, window-level recall of 0.707 at a one per cent false alarm rate and 0.897 at five per cent. Nearest neighbours follows at 0.948 AUC, then the single tree at 0.925, logistic regression at 0.909 and discriminant analysis at 0.903. The ordering by partial AUC differs from the ordering by full AUC below the top place: nearest neighbours holds second on partial AUC at 0.723 while the tree and logistic regression tie at 0.604 despite a 0.016 gap in full AUC, which is the case for reporting the partial measure rather than relying on the full one.
- **First defect, and the more serious of the two blocking ones.** Recall at a one per cent false alarm rate is not measurable for nearest neighbours as the model is currently specified. With ten neighbours the classifier's score takes only eleven distinct values across all 23,950 out-of-fold rows, so the ROC has eleven points and in fold four the highest available threshold already sits at a false alarm rate of 1.083 per cent. No operating point at or below one per cent exists, and the metric correctly but uselessly returns zero. The reported figure of 0.522 with a standard deviation of 0.294 is therefore an artefact of score granularity rather than a property of the model: the four measurable folds cluster around 0.65, and the dispersion figure is meaningless. The remedy is a model-specification change, raising the neighbour count and adding inverse distance weighting so the score is fine-grained, which requires D6.2 onwards to be rerun.
- **Second defect, also blocking.** The logistic regression score is not a posterior. Every one of the 23,950 out-of-fold values lies between 0.5001 and 0.7310, so all of them are above 0.5 and the model nominally classifies every window as aerial; the accuracy column for that family reads 0.24, which is below the 0.752 obtained by always predicting terrestrial. The ranking is unaffected, so the AUC, partial AUC and recall-at-fixed-FPR figures for that family are sound and the D6.2 conclusions stand, but the value cannot be described as a probability and the accuracy figure must not be quoted. The cause is the assumption made when the registry was written, that `fitclinear` returns the log-odds for a logistic learner so that the logistic link recovers the probability exactly; the observed range shows the returned margin is not on that scale. The remedy is to fit the family with `fitglm` under a binomial distribution, or to calibrate the margin on the training portion of each fold, and again requires a rerun. This matters beyond presentation because D6.3 averages the score across a UE's windows, and averaging an uncalibrated transform is not the same operation as averaging a posterior.
- **Third defect, in reporting rather than in method.** The achieved per-UE false alarm rate exceeds the nominal one and the console table does not say so. For the random forest the rate achieved across folds averages 1.39 per cent against a one per cent target, and per fold runs 4.17, 0, 1.39, 1.39 and 0 per cent. The mechanism is the one anticipated when the granularity warning was added, seen now at fold level: the threshold is set on roughly two hundred and eighty-eight held-in UEs, where it admits two false alarms, and then applied to roughly seventy-two held-out ones, where a single false alarm is already 1.39 per cent. The figure is recorded in `ue_rule_candidates.csv` and `ue_rule_chosen.csv` but is absent from the printed summary, so the headline recall of 0.906 at "one per cent" is in fact obtained at 1.39 per cent on average. The console report is to be extended to print the achieved rate beside the nominal one, and no per-UE figure should be quoted in Chapter 4 without it.
- **Fourth item, a genuine property rather than a defect.** The single decision tree returns 0.105 recall in fold four against 0.40 to 0.61 in the other four. Unlike the nearest-neighbour case this is not granularity, the tree's out-of-fold score taking two hundred and thirty-five distinct values, but the instability of a single tree in the low false alarm region, where one leaf carrying an unusual share of terrestrial windows moves the whole left-hand edge of the curve. It is reported as it stands, with the standard deviation of 0.197 doing the work of the caveat.
- One result that looks like a fault and is not: logistic regression and discriminant analysis return identical per-UE recall to fifteen digits, 0.591428, with identical per-fold values of 0.750, 0.4545, 0.480, 0.680 and 0.5926. The flagged UE sets were compared directly and differ in four of the five folds, and the per-UE AUCs differ at 0.927 against 0.921, so the two families are flagging different UEs and merely happen to flag the same number of aerial UEs in every fold. With around twenty-four aerial UEs per fold, recall moves in steps of about 0.042 and coincidence of this kind between two similar linear models on the same standardised features is unremarkable. It is recorded here so that it is not later mistaken for a duplicated result.
- D6.3 selected the mean posterior for all five families, no persistence rule having beaten it in any case. The margins are decisive for the random forest at 0.108 and the single tree at 0.522, and narrow for discriminant analysis at 0.072, logistic regression at 0.020 and nearest neighbours at 0.016. Within the persistence family the best performers are those with M close to N, the random forest's strongest being nine-of-ten and ten-of-ten, which is to say the rules that behave least like an extreme-value statistic. That is the expected direction: the score is defined as the maximum over blocks of the M-th largest value in the block, and at a one per cent false alarm rate a maximum taken over forty-odd blocks of a terrestrial UE's windows is heavily penalised. The conclusion that persistence does not help is therefore conditional on this encoding, and should be stated in the chapter as such rather than as a general finding about persistence rules.
- The clearest positive result of the run is that per-UE aggregation rescues the coarsely scored families. Nearest neighbours goes from a window-level recall of 0.522 at one per cent false alarm rate to 0.871 per UE, with a per-UE AUC of 0.994, because averaging fifty eleven-valued scores produces a fine-grained statistic. The random forest reaches 0.906 recall and a per-UE AUC of 0.995. Those per-UE AUCs are high enough that the caveat entered on 7 August still applies without modification: the 38.901 aerial channel model gives an airborne UE a very clean line-of-sight signature to a large number of cells, and the simulated task is materially easier than detection on a live network would be.
- D6.4 has not been run. Doing so before the two blocking defects are corrected would derive the frozen operating thresholds from a nearest-neighbour ROC that has no point at the target rate and from a logistic score that is not a probability, so the sequence is held at D6.3 until the registry is corrected and D6.2 and D6.3 are rerun.

**Deliverables:** D6.2 and D6.3 executed and their outputs written to `results/`, but both are provisional. Two model-specification defects are to be corrected before the results are used, the nearest-neighbour score granularity and the logistic regression calibration, and the per-UE console report is to be extended with the achieved false alarm rate. D6.4 to D6.7 held pending the rerun.

## Later still – defects diagnosed and corrected, with the correction verified before rerunning

**Logbook**

- The logistic regression defect was diagnosed exactly rather than worked around. Inverting the logistic link on the saved out-of-fold scores returns values spanning 0.000236 to 0.999874, which is a probability range, and the observed bounds of the corrupted score, 0.500059 and 0.731034, are the logistic function evaluated at zero and at one to six decimal places. `fitclinear` with a logistic learner therefore already returns a posterior in the second output of `predict`, and the assumption made when the registry was written, that it returns the linear predictor requiring a link, was simply wrong. The link was applied to a probability, compressing the whole development set into the upper half of the unit interval. The fix is the removal of one line: the family now uses the same scoring function as the other four.
- The correction was checked on the saved scores before committing to a rerun. Accuracy at the 0.5 threshold moves from 0.248 to 0.885, which is now comfortably above the 0.752 majority-class baseline, and the rank correlation between the corrupted and corrected scores is exactly one, confirming that every rank-based figure in D6.2 is unaffected and that only the accuracy column was ever wrong.
- One claim made earlier in this entry needs correcting. The concern that D6.3 was compromised for that family, on the grounds that averaging an uncalibrated transform is not the same operation as averaging a posterior, is right in principle but turns out not to bite here: the per-UE recall is 0.591 under both the corrupted and the corrected score, to three decimal places, with identical dispersion. Over the range the scores actually occupy the link is near enough linear that the ordering of UE means is preserved. The principle stands and the fix is still necessary, but the D6.3 figure for logistic regression was not in fact affected.
- The nearest-neighbour defect was corrected by specification rather than by patching the metric, since the metric was behaving correctly. The neighbour count goes from ten to fifty and inverse distance weighting is added, which makes the score effectively continuous, so an operating point exists wherever one is asked for; near neighbours still dominate the vote, so the larger neighbourhood does not cost the local sensitivity that motivated the small count originally. The neighbour count is now set by a measurement requirement, and the reasoning is recorded in the registry so that it is not later tuned for accuracy without regard to the consequence.
- That change was also checked ahead of the rerun, by reproducing both specifications on the same folds outside MATLAB. The distinct-score count rises from eleven to several thousand, fold four's recall at one per cent false alarm rate rises from exactly zero to about 0.69, and the window-level figure moves from 0.522 with a standard deviation of 0.263 to about 0.68 with a standard deviation of 0.047. The dispersion falling by a factor of five is the point: what looked like an unstable model was an unmeasurable metric. The AUC also improves, which was not the purpose of the change but is consistent with fifty weighted neighbours being a better estimator than ten unweighted ones on this data.
- A consequence for D6.7 should be anticipated. On the mirrored fit the nearest-neighbour family moves to roughly 0.970 window AUC and 0.890 per-UE recall against the random forest's 0.981 and 0.906, so the gap between first and second place narrows considerably and the selection may no longer be as clear-cut as the first execution suggested. The selection criterion is fixed and recorded, so this changes nothing about the procedure, but the chapter should not be drafted around the assumption that the forest wins comfortably.
- Two guards were added to `run_cv.m` so that neither defect can recur unnoticed. The first compares accuracy at the 0.5 threshold against the majority-class rate and warns when it falls below, which is the one symptom a monotone but misplaced score cannot hide from, every rank-based metric being blind to it. The second reports any fold returning exactly zero recall at the one per cent false alarm rate while holding an AUC above 0.7, which distinguishes a model that has failed to separate the classes from a score that has failed to offer an operating point; the two look identical in a results table and call for opposite responses. A range assertion was also added to the shared scoring function, though it is worth noting that it would not have caught this particular fault, the corrupted scores having remained inside the unit interval throughout.
- The per-UE console report now prints the achieved false alarm rate beside the nominal one and names any family whose achieved rate exceeds the target by more than a fifth, which on the first execution would have flagged the random forest at 1.39 per cent against a one per cent target.

**Deliverables:** three corrections applied to `phase6_models.m`, `run_cv.m` and `per_ue_rule.m`, each verified against the saved out-of-fold scores before rerunning. D6.2 and D6.3 to be re-executed and their earlier outputs discarded; the results recorded above are superseded except where noted as unaffected. D6.4 to D6.7 to follow once the rerun is confirmed clean.

## Rerun of D6.2 and D6.3, and a change to the D6.7 selection criterion

**Logbook**

- Both corrections behaved as the pre-checks predicted. Nearest neighbours now returns per-fold recall at a one per cent false alarm rate of 0.591, 0.708, 0.729, 0.686 and 0.687, against 0.703, 0.665, 0.637, zero and 0.607 before, so the fold that previously returned nothing now sits with the rest. The summary figure moves from 0.522 with a standard deviation of 0.294 to 0.680 with a standard deviation of 0.053, and the AUC from 0.948 to 0.970. Both the AUC and the recall agree with the Python reproduction to three decimal places, which is a useful independent check on the MATLAB fit rather than merely on the arithmetic around it.
- Neither of the new guards fired, which is the intended result: logistic regression now scores 0.885 accuracy at the 0.5 threshold against a 0.752 majority-class baseline, and no fold returns zero recall while holding a high AUC. The remaining four families returned figures identical to the previous execution in every digit, confirming that the change was isolated to the two families it was aimed at and that the pipeline is reproducible under a fixed seed.
- The per-UE table now prints the achieved false alarm rate, and the first thing it shows is that the families are not being compared on equal terms. The random forest reaches 0.906 recall at an achieved rate of 1.389 per cent while nearest neighbours reaches 0.890 at 0.833 per cent, so the forest is buying 1.6 points of recall with two thirds more false alarms, and the criterion as originally specified was rewarding it for the overshoot. The console now names any family exceeding the target by more than a fifth, which on this run is the random forest.
- Pooling the out-of-fold per-UE scores removes that asymmetry, because three hundred and sixty terrestrial UEs admit three false alarms and no other number, so every family is forced to an achieved rate of exactly 0.833 per cent. On that footing the random forest reaches 0.9076 and nearest neighbours 0.8992, which is one hundred and eight against one hundred and seven of the one hundred and nineteen aerial UEs. **The selection of a primary classifier was therefore resting on a single UE.** Recall at a fixed operating point cannot carry the decision on a development set this size, and the fold-wise version of the same figure is worse still, a fold holding around seventy-two terrestrial UEs and so resolving the false alarm rate only in steps of about 1.4 per cent.
- The D6.7 criterion was changed accordingly, from per-UE recall at the one per cent operating point to the per-UE partial AUC below a five per cent false alarm rate, computed on the pooled out-of-fold scores under each family's own decision rule. It is free of both faults: no threshold is involved, so no family can profit from overshooting one, and it integrates the whole region an operator could work in rather than one discrete point inside it. On the current run it separates the leaders by 0.026, the random forest at 0.9290 against nearest neighbours at 0.9029, which is a margin the data can actually support. Recall at one per cent is retained in the manifest and remains the figure to quote for the chosen model; it is reported rather than used to choose.
- The change does not alter which family is selected, the random forest leading on both measures, and it was made for that reason with some care: it is a change to how a conclusion is justified rather than to the conclusion, and it was decided on the structure of the comparison rather than on which answer it produced. Paired by fold the forest's advantage over nearest neighbours is significant on AUC, a mean difference of 0.0104 with a standard error of 0.0029 and four folds of five, but not on recall at one per cent, where the mean difference of 0.0265 carries a standard error of 0.0209. The new criterion agrees with the measure that discriminates and discards the one that does not.
- A warning was added that fires when the top two families are separated by less than 0.01 on the criterion, so that a near-tie is reported as a near-tie rather than presented as a result. It does not fire on the current run.
- Two smaller observations from the rerun. The single decision tree still returns 0.105 in fold four against 0.40 to 0.61 elsewhere, unchanged and still attributable to single-tree instability in the low false alarm region rather than to score resolution. Logistic regression and discriminant analysis, which returned identical per-UE recall fold by fold and were checked at the time and found to be flagging different UEs, now separate cleanly under pooled scoring at 0.6134 and 0.5966, which closes that question.
- The nearest-neighbour family is now a genuine second rather than a distant one, at 0.970 window AUC and 0.9992 of the forest's per-UE AUC, and the chapter should present the top two as close rather than implying a comfortable margin. That both a distance-weighted nearest-neighbour classifier and a bagged forest reach this level on thirteen radio and mobility features is itself worth a sentence: it suggests the separation in this dataset is carried by the feature geometry rather than by any particular model family, which strengthens the existing caveat that the 38.901 aerial channel model makes the simulated task materially easier than detection on a live network.

**Deliverables:** D6.2 and D6.3 complete and clean, with results in `results/cv_results.csv`, `results/cv_results_perfold.csv`, `results/ue_rule_candidates.csv` and `results/ue_rule_chosen.csv`. The D6.7 selection criterion changed to the pooled per-UE partial AUC below a five per cent false alarm rate, with the reasoning recorded in `freeze_models.m`; `per_ue_rule.m` extended to compute and report the pooled comparison. D6.3 to be re-executed once so the pooled columns are written, after which D6.4 to D6.7 can proceed.

## D6.4 to D6.6 executed, a duplicated predictor found, and what the results actually support

**Logbook**

- The pipeline was run through to D6.6. D6.4 fixes the primary operating point at 0.908 per-UE recall for the random forest, achieved at 0.833 per cent false alarm rate, which is one hundred and eight of the one hundred and nineteen aerial UEs caught for three false alarms among three hundred and sixty terrestrial ones. The five per cent sensitivity point gives 0.966 recall for eighteen false alarms. At window level the same model gives 0.716 recall at 0.978 per cent and 0.897 at 4.928 per cent. Every family lands on the same three false alarms at the per-UE level, the pooled negative population admitting no other number, so the four families are directly comparable there.
- The interval on that headline figure should be quoted with it. On one hundred and nineteen aerial UEs a recall of 0.908 carries a 95 per cent Wilson interval of 0.842 to 0.948, and three false alarms in three hundred and sixty terrestrial UEs gives an interval of 0.28 to 2.42 per cent on the false alarm rate. The defensible claim is therefore that the detector catches roughly eighty-five to ninety-five per cent of aerial UEs at roughly a third of a per cent to two and a half per cent false alarms, not that it achieves 90.8 per cent at 1 per cent. The limiting quantity is the number of aerial UEs, not the number of windows, which is the same conclusion the dataset sizing reached on 24 July and is worth restating now that it binds a reported result.
- The comparison between the window-level and per-UE figures is the practical argument for D6.3 existing. A one per cent window-level false alarm rate is one hundred and eighty false alarms among the eighteen thousand terrestrial windows in the development set, which no operator could act on. Aggregating a UE's windows into one score takes the same model from 0.716 to 0.908 recall while reducing the decision count by a factor of fifty. Single-window detection is not deployable and the per-UE rule is what makes the approach viable.
- D6.5 gives the most operationally interesting result of the phase. The random forest reaches 0.782 recall from a single ten-second window, at the same 0.833 per cent false alarm rate held constant across every observation length, and rises to about 0.88 by twenty-six windows. The two linear families need twelve to fifteen windows merely to reach 0.50. Detection therefore does not require a long dwell, and the advantage of the ensemble over the linear models is largest when the observation is shortest, which is the opposite of what a longer averaging window would be expected to fix.
- **A duplicated predictor was found in the feature set.** `hoRate_perS` and `hoCount_win` correlate at 1.000000000 because the analysis window is always exactly ten seconds, so one is ten times the other; the switchboard has been carrying twelve real predictors under the impression it carried thirteen. This survived every existing check, being neither empty, constant, nor a leak. Its effect falls on D6.6: permutation importance divides between perfect surrogates, since permuting one leaves the other for the forest to fall back on, so the handover block was reported as two unimportant features at ranks 10.0 and 11.6 rather than as one feature of roughly their combined weight. `hoRate_perS` has been switched off and a collinearity tripwire added to `prepare_data.m`, which now refuses to proceed on any selected pair correlating at 0.999 or above and prints a note at 0.95 or above. With the duplicate removed the strongest remaining pair is 0.927, so the tripwire will pass silently and no notes will print.
- Two further faults were found in the D6.5 reporting, neither affecting the underlying curve. The table of observation lengths reported the first crossing of a recall level rather than the first sustained one, and because re-deriving the threshold at each length makes the curve non-monotone, the random forest was credited with reaching 0.80 recall after three windows on the strength of a transient touch at 0.807 that fell back to 0.765 by window eight and did not hold until window thirteen. Nearest neighbours, whose curve rises monotonically, was correctly reported at twenty-one, so the table made the two families look far more different than they are. `firstReach` now takes the running minimum from each point to the end of the curve and reports the length from which the level is held for good. Separately, the curve was truncated at thirty windows although every UE carries fifty, so all four hundred and seventy-nine UEs survive to the full trajectory at no cost in population; the 0.90 level was reported as unreached when the pooled full-trajectory figure is 0.9076. The limit is now fifty.
- D6.6, read with the duplicate caveat in mind, gives the result the project most needs. The discriminative load sits on neighbour-cell geometry: the mean neighbour SINR ranks first on the combined measure with a single-feature AUC of 0.878, the maximum neighbour SINR third, and the mean count of neighbours above threshold fifth at 0.843. Four of the top five features fall in blocks judged hard for a UE to manipulate, because the network measures them rather than the UE reporting them. The exception is the mean CQI at rank two, which is UE-reported and provisionally judged of medium manipulability, and which carries the highest single out-of-bag importance of any feature at 3.890 despite a single-feature AUC of only 0.652; it is doing work in combination rather than alone. This is the security argument for the whole approach and should be made explicitly in Chapter 4: a detector resting on quantities the UE controls could be defeated by the UE, and this one largely does not.
- Two features earn a caveat in that ranking. `sinrSpread_mean_dB` and `nbrSINR_max_var_dB2` have single-feature AUCs of 0.522 and 0.502, which is to say no standalone discriminative power whatever, yet both carry high out-of-bag importance at 3.024 and 3.818. Either they contribute only through interaction, which is plausible for a spread and a variance conditioned on the level, or the forest is using them as convenient split variables without their carrying signal. The distinction matters for the manipulability argument and is worth a paragraph rather than a sentence.
- The overall assessment is that the classifier is good but that the reason it is this good needs stating before the number is. A window AUC of 0.981 and a per-UE AUC of 0.995 are high enough to invite scepticism, and the explanation is the one already entered on 7 August: the 38.901 aerial channel model gives an airborne UE clean line of sight to a large number of cells at once, which is precisely what the strongest features measure. It should be made explicit that Phase 7 will not test this. The hold-out runs come from the same simulator, so they test generalisation across seeds and not across the gap between simulation and a live network, and the chapter should not let the hold-out result be read as evidence about the latter.

**Deliverables:** D6.2 to D6.6 executed. Three corrections applied: `hoRate_perS` switched off in `prepare_data.m` with a collinearity tripwire added, `firstReach` in `phase6_util.m` changed to report sustained rather than transient crossings, and the latency curve extended from thirty windows to the full fifty. The duplicate requires a rerun from `prepare_data.m`; D6.2 to D6.5 results are unaffected in substance but D6.6's ranking is superseded. D6.7 to follow the rerun.

## Rerun on twelve predictors: results as they stand, and why they are not being finalised

**Logbook**

- The pipeline was rerun end to end on the corrected feature set of twelve predictors. The collinearity tripwire passed silently and printed no notes, confirming that the strongest remaining pair sits below 0.95, and no family now overshoots the per-UE false alarm target, so both warnings added earlier are quiet for the right reasons rather than because they are ineffective.
- Removing the duplicated handover column cost the random forest a little, which is the expected direction and slightly reassuring. Its window AUC moves from 0.981 to 0.979 and its pooled per-UE recall from one hundred and eight of one hundred and nineteen aerial UEs to one hundred and seven; nearest neighbours moves marginally the other way. Carrying the same quantity twice had given the forest two chances to split on the handover signal and was mildly inflating it, so the earlier headline was optimistic by about one UE. The present figures are the honest ones.
- The two leading families now tie exactly. Both the random forest and nearest neighbours catch one hundred and seven of the one hundred and nineteen aerial UEs at the pooled operating point, both at three false alarms in three hundred and sixty, and both return a per-UE AUC of 0.9944. The selection criterion separates them by 0.0086, which falls below the 0.01 threshold set when the criterion was adopted, so the near-tie warning will fire at D6.7. That is the guard behaving as intended: on full-trajectory detection these two families are not distinguishable on this development set and the chapter must not pretend otherwise.
- The tie is not superficial, and the structure underneath it is worth recording. The two families agree on one hundred and four aerial UEs, each uniquely catches three that the other misses, and both miss the same nine. Their union would catch one hundred and ten of one hundred and nineteen at the same three false alarms, which is better than either alone. Combining families falls outside the five listed in D6.1 and no attempt has been made to exploit it, but it belongs in the further work section: the errors of a distance-based and a tree-based classifier on this task are partly independent, and the nine UEs both miss are the ones worth examining for what makes an aerial trajectory look terrestrial.
- What does separate the two families is detection latency, and by a wide margin. From a single ten-second window the forest reaches 0.782 recall against 0.529 for nearest neighbours, and it holds 0.80 from twelve windows against nineteen. The two converge by about window twenty and are identical from window forty-five onward. The forest is therefore better precisely where the operational value lies, in deciding quickly, and equivalent where it does not. This is cross-validation evidence like any other and is admissible in the D6.7 justification alongside the partial AUC; it is the stronger of the two arguments and should be presented as such.
- Neither leading family reaches 0.90 recall at any observation length, but the shortfall is one UE: one hundred and seven caught where one hundred and eight would be needed. Reporting that as "not reached" is accurate and misleading in equal measure, and the chapter should give the count rather than the level.
- D6.4 records the operating points on the corrected features. At the per-UE level every family sits at three false alarms in three hundred and sixty, with the forest and nearest neighbours at 0.899 recall, the single tree at 0.857, logistic regression at 0.613 and discriminant analysis at 0.597. At the five per cent sensitivity point the forest reaches 0.975. At window level the forest gives 0.704 recall at 0.939 per cent, which is one hundred and sixty-nine false alarms among eighteen thousand terrestrial windows and remains the clearest demonstration that window-level decisions are not deployable.
- One reporting fault was corrected in `thresholds.m`. It named the family with the best per-UE recall by taking the first row of a sorted table, which on a tie named whichever family happened to sort first, and on this run it announced nearest neighbours as best when the forest scores identically. It now reports ties as ties and defers to the partial AUC. An arbitrary tie-break printed as a finding is precisely the sort of thing that survives into a chapter unchallenged, so the fix matters more than its size suggests.
- D6.6 consolidated as predicted once the duplicate was removed. The handover count rises from 1.685 to 2.329 on out-of-bag importance and from rank 10.0 to 9.4, recovering the share that had been going to its own copy. The ordering is otherwise stable: mean neighbour SINR first, maximum neighbour SINR and mean CQI joint second, mean count of neighbours above threshold fourth, mean serving SINR fifth, with four of the top five in blocks judged hard for a UE to manipulate. The two features with no standalone signal, the mean SINR spread at a single-feature AUC of 0.522 and the neighbour SINR variance at 0.502, retain high out-of-bag importance and still want explaining.
- **These results are not being finalised.** The Phase 5 dataset is being regenerated with RSSI, RSRP and RSRQ included, on the grounds that they are the measurements an operator actually holds and their absence is a real gap in the feature schema rather than a simplification. Phase 6 is therefore being fleshed out rather than closed: the scripts, the fold structure, the decision rule, the threshold derivation and the reporting are all settled and should not need revisiting, but every number recorded above is provisional and will be superseded by the rerun on the new feature set. D6.7 has deliberately not been run, since freezing a pipeline and recording a freeze date against a superseded dataset would defeat the purpose of freezing it.
- Three things to expect when the new features arrive. First, `prepare_data.m` will refuse to run until each new column has an entry in the switchboard, by design, so the error is expected and is not a fault. Second, the collinearity tripwire is likely to have something to say: RSRQ is a function of RSRP and RSSI, and all three are closely related to the serving and neighbour SINR features already in use, so at least one near-duplicate pair is probable and the switchboard will need a decision rather than the default of switching everything on. Third, and most consequential for D6.6, these are UE-reported measurements carried in RRC measurement reports rather than quantities the network derives for itself, so their manipulability is arguably medium rather than low. If they displace the neighbour-SINR features at the top of the ranking, the security argument that currently rests on four low-manipulability features in the top five weakens, and that would be a genuine finding about the approach rather than a problem with the pipeline. It is worth deciding in advance how the manipulability column should treat measurement-report quantities, since deciding it after seeing the ranking would not be defensible.

**Deliverables:** D6.2 to D6.6 executed on twelve predictors and recorded here in full, all figures provisional pending the Phase 5 regeneration with RSSI, RSRP and RSRQ. One reporting fault corrected in `thresholds.m`. D6.7 deliberately not executed: a freeze against a superseded dataset would be worthless. The Phase 6 scripts themselves are considered settled and are expected to carry over to the new feature set unchanged apart from switchboard entries and a manipulability judgement for the new measurement-report features.
