# Friday 7 August 2026 – Phase 6 leakage audit, split specification and script restructure

**Logbook**

- A single-feature separability audit was added to `prepare_data.m` and run over the pooled dataset of thirty-five completed runs. Each predictor was scored on its own against the label, and four were found to separate the two classes perfectly, in the sense that their terrestrial and aerial value ranges do not overlap at any point: uplink volume, uplink throughput, uplink grant rate and the downlink-to-uplink asymmetry ratio. A further seven exceeded a single-feature AUC of 0.95, among them the traffic idle fraction, which is exactly zero for every aerial window in the dataset.
- The cause was traced to the Phase 5 traffic configuration rather than to any fault in the Phase 6 code. Aerial UEs were assigned an uplink-heavy, continuously active application model and terrestrial UEs a bursty downlink-heavy one, so these columns record the application profile chosen at simulation setup rather than any radio consequence of the UE being airborne. Any classifier trained on them reports an AUC of 1.000 by reading the experimental design back out of the feature table, which would have invalidated the whole of D6.2 had it gone unnoticed.
- This is the same category of leakage that the loader's existing line-of-sight and altitude guard was written to prevent; it entered through the traffic columns because the guard tests column names against a fixed pattern and these names carry no obvious warning. The separability audit was therefore made permanent: `prepare_data.m` now computes the single-feature AUC of every predictor on the training partition before any model is fitted, writes the full ranking to `prepared_data/leakage_check.csv`, and prints a warning naming anything at or above 0.99. Anything flagged that falls outside the known traffic block is to be treated as an unexplained confound and investigated before results are used.
- Sixteen volume and scheduling-load columns were grouped into a named traffic block in `phase6_LoadDataset.m`, which now returns a logical mask over the predictor names rather than dropping the columns. The block was defined on the principle that every member is derived from the application model, not by selecting on measured AUC, so that removing it constitutes a clean ablation rather than a post-hoc trim. Forty-six radio and mobility predictors remain when it is excluded.
- An `includeTraffic` toggle was added to every train and test script and to both batch scripts, with the batch setting inherited by the individual scripts. Trained models and their outputs are tagged `_radioonly` or `_withtraffic` so both variants coexist on disk and the ablation can be reported as two tables. The radio-only setting is the default and is the one the chapter should quote.
- The train and test partition is no longer drawn at random. Two seed ranges are now declared at the top of `prepare_data.m`, seeds one to twenty-four for training and twenty-five to thirty-six for testing, so the same runs fall on the same side on every execution and the ranges can be quoted directly in the methodology. Because Phase 5 cycles the three scenarios one per run, a contiguous range is self-stratifying: the training range yields exactly eight UMa, eight RMa and eight UMi runs. The script now reports which seeds were used on each side, per scenario, with run and row counts, and checks the declared ranges against what is present on disk.
- That check identified seed thirty-four, a UMa run, as absent from the data directory. It is the reason the test partition holds three UMa runs against four for each of the other scenarios. Whether the run failed during Phase 5 or was never queued has not yet been established.
- Several corrections were made to the model definitions themselves. Logistic regression was the one materially incorrect model: `fitclinear` applies a ridge penalty, which is not invariant to predictor scale, while the predictors span standard deviations from roughly 0.03 to two million, so the penalty was falling almost entirely on the decibel-scale features. The predictors are now standardised using training statistics only, which are saved with the model and reapplied at test. A fixed random seed was added to every training script, since bagging is stochastic and results were not previously reproducible. A minimum leaf size of twenty was imposed on the single decision tree to stop leaves being formed from a handful of near-duplicate overlapping windows. Both scripts that build a random forest were corrected to pass an explicit integer to `NumVariablesToSample`, which does not accept the string `'sqrt'`. The data directory paths in `prepare_data.m` and `run_cv.m`, both of which pointed at folders that do not exist, were resolved from the script location instead.
- Reporting was extended beyond the default decision threshold. Because the aerial class is about a quarter of the rows, accuracy is a weak summary, and because the false alarm rate is the binding operational constraint at network scale, each test script now also reports the recall still available at one and five per cent false alarm rates, read off the test ROC curve. This is a property of the curve rather than a tuned operating point; a threshold selected on the training partition was considered and rejected, as the in-sample scores of the forest and the nearest-neighbour classifier are close to degenerate and would calibrate it meaninglessly.
- Predictor importance outputs were added for the write-up. The random forest writes out-of-bag permuted importance, measured on rows each tree did not train on, and logistic regression writes its standardised coefficients as a second, linear view of which features carry the signal.
- Two batch scripts were written. `train_all.m` fits all five models in sequence and `test_all.m` evaluates them and writes a single comparison table sorted by AUC. Both call the individual scripts rather than redefining the models, so each model has exactly one definition.
- The folder was reorganised into `train/`, `test/`, `models/` and `prepared_data/`, with `prepare_data.m`, `train_all.m`, `test_all.m` and `run_cv.m` remaining at the Phase 6 root. Scripts in the subfolders locate the root from the shared loader rather than from `mfilename`, because `run` evaluates a called script in the caller's workspace and `mfilename` would return the calling script's name.
- A cross-check of the pipeline in Python, pending the MATLAB run, indicates the ablation is stark. With the traffic block included every one of the five families returns an AUC of 1.000. With it excluded the families separate, ranging from about 0.94 for the single tree to about 0.97 for nearest neighbours and logistic regression, with the strongest single radio predictor being the mean neighbour-cell SINR at about 0.86. These figures are indicative only and are to be replaced by the MATLAB output.
- The random forest remains close to 0.999 on radio features alone, which is high enough to warrant a caveat in Chapter 4 rather than being reported at face value. The 38.901 aerial channel model gives an airborne UE a very clean line-of-sight signature to a large number of cells, so the simulated task is materially easier than detection would be on a live network.

**Deliverables:** D6.1 complete. Thirteen MATLAB scripts across four subfolders, with a leakage tripwire, a declared seed-range split and a traffic-block ablation switch. D6.2 pending the MATLAB execution of `train_all.m` and `test_all.m` under both toggle settings, and pending a decision on whether to regenerate the Phase 5 runs with a common traffic model for both UE types.
